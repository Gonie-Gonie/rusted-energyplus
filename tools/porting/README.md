# CON-01 input preparation and reference observations

From the repository root:

```powershell
python tools/porting/prepare_con01.py
python tools/porting/prepare_con01.py --check
python tools/porting/trace_con01.py
python tools/porting/trace_con01.py --rust-cli target/debug/eplus-rs.exe
python tools/porting/trace_con01.py --unit-settings --rust-cli target/debug/eplus-rs.exe
python tools/porting/check_con01_admission.py
```

`prepare_con01.py` verifies original byte hashes before creating 15 pinned IDFs,
metadata, and four contracts. It replays each declared patch record to detect
undocumented input changes. `--check` compares generated bytes without writes.
No tool in this workflow changes card gates, `plan.json`, or checklist views.
`scope.json` contains compact case bindings and SHA-pinned metadata references;
the runner verifies those hashes and identities before loading expected settings
and patches. Named output tolerance rows are stored once in A/B profiles, with
explicit production and unit-case profile maps. Shared weather bytes remain in
the installed resource directory.
Two separate settings probes live in `evidence/CON-01/unit-settings`: signed
north-axis normalization with min30/max25 warmup correction, and positive-axis
normalization with blank warmup defaults min1/max25. They are excluded from the
15 production-case matrix. `--unit-settings` runs their paired EP/Rust settings
checks and writes a separate execution matrix.

The default trace run executes five 24-hour cases: unconditioned A and B with
NoLimit, flow, capacity, and both limits. Each has one weather environment and
96 accepted zone steps after warmup. `--case A-72H` or an annual case explicitly
selects another duration. Preparing a case does not execute it. The execution
matrix records missing reference evidence as `not_run`.

The weather file stays at its SHA-pinned installed path; it is not duplicated.
Input years and weekdays use the 2013 civil calendar, separate from each TMY
weather record year.
Civil/weather ordinals use the 2013 non-leap calendar. Schedule ordinals use
EnergyPlus's canonical 366-day lookup table; June 30 is schedule ordinal 182,
separate from civil/weather ordinal 181. Both meanings stay explicit.
A retains its two DesignDay definitions, but sizing and sizing-period simulation
are disabled. It also retains exterior lights as an
exterior-meter feature with no zone heat source. No OA, humidification,
dehumidification, autosizing, or non-Mixing room-air branch is enabled for B.
B has a shared system-availability schedule: daily first three hours Off and
remaining 21 hours On. The declared branch, patch, name binding, and schedule
output are explicit. Observed zero delivery in availability-zero intervals
checks the selected input; internal Heat/Cool/DeadBand/Off phase completion is
still gated by HVAC-03/SYS-06.
A retains surface-derived Zone ceiling-height/volume `Autocalculate`; this
belongs to geometry cards and is separate from excluded HVAC equipment sizing.

The observer requests output variables and reads them through EnergyPlus API
callbacks. It never sets actuators or supplies predictor/corrector/HVAC values.
Callback JSONL, complete ESO/EIO, logs, and exchange points stay below
`.runtime/porting/CON-01/reference`. Checked-in evidence contains hashed
summaries, relevant EIO rows, and a compact 96-step zone trace. The raw system
trace retains adaptive timestep durations. System-variable values read at the
zone-report callback are instantaneous report fields; numerical Timestep
comparison must use ESO Average/Sum output or aggregate accepted system samples.

Two API clock meanings matter: `year()` reads the EPW record year, while
`calendar_year()` reads the civil year. At the end-zone callback after shortened
system timesteps, `current_time()` can be canonical zone-end time plus the last
system duration. Both raw API fields are retained. Canonical zone timestamps
are checked exactly against the ESO Timestep timestamps.

`--rust-cli` invokes `eplus-rs run ... --porting-scope A|B --dry-run` through the
real production entrypoint. It compares project controls, hard limits, civil
calendar frame, DST, and prepared schedule arrays with reference observations.
The bounded dry run does not execute Rust physics. A CON-01 result cannot certify
geometry, psychrometrics, CTF coefficients/history, heat-balance numerics,
predictor/corrector, IdealLoads, adaptive timestep acceptance, or annual results;
those retain their own card gates. A zero-delivery output sample cannot identify
Off versus deadband without the later internal-state contract.

`check_con01_admission.py` runs all 15 frozen IDFs through the real bounded Rust
dry-run entrypoint, validates controls, hard limits, calendar frames and all
declared prepared schedule values, and saves a compact matrix with command/log/
trace hashes. It also creates three separately patched negative inputs (latent
gains, OA, Autosize), then requires RunBlocked/unsupported exit 4 and specific scope violations.
Their IDFs, source hashes and patch metadata are retained for direct CLI replay.
The full annual prepared arrays and logs remain under `.runtime`; 72H/annual
EnergyPlus simulation and Rust numerical comparison remain unexecuted.

The runner records implementation artifacts and reference DLL hashes as well as
the repository revision. Evidence created from an uncommitted working tree is
identified by those exact hashes. Review and gate promotion remain explicit.
