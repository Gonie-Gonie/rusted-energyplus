# Maintenance scope

The 0.2.0 release closes the current delivery work around the verified bounded
Source implementation. Its scope is recorded in [supported inputs](../guides/supported-inputs.md)
and the complete [object inventory](../generated/example-object-union.md).

Maintenance covers reproducible builds, package usability, accurate support
reports, documentation and defects within those boundaries. Changes use the
existing focused tests and the release package check.

Broader object/parameter porting is deferred. Active windows and the other
excluded families are not current delivery promises. A future expansion needs
its own explicit scope, connected implementation and same-input numerical
evidence before its support label changes.

Past task cards, plans and chronological work logs remain in Git history and
retained evidence; they are not the current user workflow.
