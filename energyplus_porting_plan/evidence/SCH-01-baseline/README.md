# SCH-01 기존 구현 비교 기록

2026-10-10에 clean commit `b4f1a9a8a67534128369236ca720351d08933d06`의 기존 Rust 구현을 고정된 EnergyPlus 26.1.0 원본과 비교했다. 수정 전 결과이며 SCH-01 완료 또는 전체 수치 통과를 주장하지 않는다. 입력 82개, 요청된 작업 164개, 사전 고정된 ID 대응·가용성·정밀도 정책을 유지했다.

실제 원본 실행 82개 중 80개는 프로세스 종료 0으로 결과를 남겼고 두 개는 종료했다. 관찰 가능한 80개 결과의 실제 함수 호출은 입력 처리 80회와 스케줄 처리 77회다. 나머지 두 사례의 함수 결과와 호출 횟수는 미확인이다. 원본 결과 검토의 종료 0은 이 구분과 실제 데이터 형식·출처를 확인했다는 뜻이다.

디버거는 연간 기간 누락 사례의 빈 week 포인터 참조(`ScheduleManager.cc:3332`)와 값 누락 사례의 배열 범위 검사 위반(`Array1.hh:861`, index 7, 호출자 `ScheduleManager.cc:1444`)을 확인했다. 디버거 자체의 종료 0을 원본 성공으로 취급하지 않았다. 원본 코드와 실행파일을 수정하여 이 사례를 통과시키지 않았다.

실제 엄격 비교는 수치 7,592,089개 중 불일치 0개, 이산 비교 281,539개 중 불일치 295개, 필수 가용성 실패 139개를 기록했다. ID와 owner가 다른 값은 이름으로 재배치하여 비교하지 않았다. 따라서 수치 불일치 0개는 모든 입력의 값이 비교되었다는 뜻이 아니다. 실제 변환기가 종료 0으로 epJSON을 남기지 않은 세 사례도 Rust 미호출·미가용으로 유지했다.

`summary.json`은 요약이며 `manifest.json`은 전체 비교 보고서, 실제 실행 기록·로그, 원본 결과, 고정 입력과 검토한 소스의 보관 위치를 연결한다. 각 행의 `historical_path`는 실행 당시 경로다. `storage.parts`를 순서대로 연결하고 `codec`이 `gzip`이면 압축을 풀면 원래 바이트를 복원할 수 있다. 모든 선택 바이트를 복원하여 길이와 SHA-256을 확인했다. 중복 저장 객체는 공유하며 객체 하나는 4MB 이하다. 실행파일·라이브러리는 복사하지 않았다.

다음 수정 대상은 선언·등록 순서, 실제 단위 메타데이터 owner, 선정 입력의 경고·허용 처리와 실제 timestep 값에 대한 TypeLimits 검사다. 수치 허용오차와 미가용 판정은 그대로 유지한다. SCH-01의 네 완료 항목은 계속 미확인이다.
