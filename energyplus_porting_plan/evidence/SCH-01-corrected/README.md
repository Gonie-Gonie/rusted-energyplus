# SCH-01 수정 후 실제 비교와 생산 인계

선언 순서·ID, 실제 단위 owner, Compact 허용·경고·TypeLimits 검증을 원본과 맞춘 뒤 실제 Rust 실행을 비교했다. 단위 관찰 비교는 수치 21,508,632개·이산 716,890개, 선정 생산 입력 6개의 저장된 초기화·인계 비교는 수치 10,119,332개·이산 316,842개에서 불일치 0개다. 모든 수치 profile의 atol/rtol=0을 유지했다.

이는 SCH-01 전체 완료를 뜻하지 않는다. Native 비정상 종료 두 사례의 필수 가용성 실패 2개와 변환 결과가 없는 세 사례는 남아 있다. Dense cache 1,824개 값은 class/shape만 확인했다. 개별 lookup 시각, SCH-02/03 계산, 나머지 생산 입력 9개는 검증하지 않았다. RMSE는 별도 수집하지 않았다.

`summary.json`은 실제 보고서의 요약이다. `manifest.json`의 `historical_path`는 실행 당시 경로이며 각 행의 `storage.parts`를 순서대로 연결한 뒤 `codec`이 `gzip`이면 압축을 풀어 원래 바이트를 복원한다. 모든 선택 바이트의 복원 길이와 SHA-256을 확인했다. 기존 baseline과 같은 바이트는 `../SCH-01-baseline/` 객체를 재사용한다. 실행파일·라이브러리, 다른 카드의 대용량 결과, 이번 비교와 무관한 생산 trace는 복사하지 않았다. 저장소 전체의 참조 closure를 주장하지 않는다.

실제 candidate 단위 보고서, 두 번의 생산 실행 기록, 최종 비교, 실행·빌드·품질 검사 기록과 실패 이력, 고정 입력·정책, 선택한 소스 bytes를 보존했다. 첫 번째 생산 비교는 실제 종료 1이며 원인은 입력에 Compact family가 없는 경우의 provenance 검사였다. 해당 실패와 원래 비교 소스를 남기고, 두 predicate만 수정한 별도 소스를 검토한 뒤 생산 6개를 새로 실행했다. 두 번째 비교는 실제 종료 0이다. 실패한 실행을 성공으로 바꾸어 기록하지 않았다.

생산 CLI는 실제 실행 직전 빌드된 `df865d96a56c36b6dfc3011994c0525c351ecce0` 소스와 연결된다. 초기 candidate는 `47c0dedbfe296e86075671dc112d9c81bf3956cf`에서 관찰했다. 실제 receipt와 source snapshot이 각 실행의 정확한 상태를 보존한다. Native 결과는 비교 기준으로만 사용하며 Rust 생산 계산에 전달하지 않았다.
